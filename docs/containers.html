Docker & Apptainer

Keep Docker on the workstation. Run the same container software with Apptainer on HPC.

Choose your runtime

WhereRuntimeImage
WorkstationDocker (default)Image in the Docker daemon
HPCApptainerA prepared .sif file

The nine container launchers accept --container docker|apptainer. Existing commands keep using Docker; there is no automatic runtime switching. The Snakefile and analysis options stay the same.

# Existing workstation command: Docker remains the default.
bash shortWGS/Go_shortWGS.sh [existing options]

# Explicit workstation selection.
bash shortWGS/Go_shortWGS.sh --container docker [existing options]

# HPC: select an existing SIF file.
bash shortWGS/Go_shortWGS.sh --container apptainer \
  --container-image "$HOME/containers/shortwgs.sif" [existing options]

Replace [existing options] with the pipeline's required input and database options. --container-image selects a Docker image or SIF file. Existing -m image options also work; longWGS uses --container-image because it has no image -m option.

This applies to longWGS, shortWGS, RNake, PFsnake, KBracken, Humann, and all three MAGs stages. daDake2 and merge/rename utilities keep their host execution. TnSeq_ONT has a Python entry point; see its direct Apptainer example.

Move an existing Docker image to HPC

Docker image→ Export TAR→ Transfer to HPC→ Build SIF→ Run Apptainer

The steps below reuse your existing workstation image. No separate Apptainer package installation recipe is needed.

1. Locate the image — on the workstation

docker image ls
docker context show
docker info --format '{{.DockerRootDir}}'

Run these commands on the workstation where the image was built. Select its REPOSITORY and TAG. DockerRootDir is the active daemon's internal storage directory, commonly /var/lib/docker on Linux or a directory inside the Docker Desktop VM. A remote context points to the remote daemon. Export an image with docker save instead of copying internal storage files.

Check the actual image list before exporting. The image CPU architecture must match the HPC.

2. Export — on the workstation

From the repository root:

bash common/Go_container_image.sh export shortwgs \
  container-images/shortwgs.docker.tar

This creates the archive and an .image.txt file with the source image ID, OS/architecture, and tags. Existing output files are not overwritten. For another pipeline, change the image name and output filename.

Equivalent manual commands 
mkdir -p container-images
docker save --output container-images/shortwgs.docker.tar shortwgs

Use docker save; docker export exports a container filesystem rather than the image configuration.

3. Transfer — from the workstation to HPC

Replace USER@HPC_HOST with your login or institution-recommended transfer host.

ssh USER@HPC_HOST 'mkdir -p ~/containers'
rsync -avP container-images/shortwgs.docker.tar \
  container-images/shortwgs.docker.tar.image.txt \
  USER@HPC_HOST:~/containers/

rsync -avP shows progress and retains partial files for interrupted transfers. Prepare the code on HPC too:

# On HPC: first-time checkout.
git clone https://github.com/bbagy/UhlemannLab.git
cd UhlemannLab

# For an existing checkout, check local changes before updating.
# git pull --ff-only

4. Convert to SIF — on HPC

Load the site-specific Apptainer module if needed. Convert on a node or within an allocation where your cluster permits builds, with enough temporary and output storage.

module load apptainer  # Omit if already available; module names vary by site.
cd ~/UhlemannLab
bash common/Go_container_image.sh build \
  "$HOME/containers/shortwgs.docker.tar" \
  "$HOME/containers/shortwgs.sif"
Equivalent manual command 
apptainer build "$HOME/containers/shortwgs.sif" \
  "docker-archive:$HOME/containers/shortwgs.docker.tar"

Use docker-archive: followed by the file path. Conversion from the archive does not require a Docker daemon or registry download on HPC. If HPC builds are not permitted, convert on another Linux machine with Apptainer and transfer the SIF instead.

5. Check the tools and run — on HPC

apptainer exec --cleanenv "$HOME/containers/shortwgs.sif" snakemake --version
apptainer exec --cleanenv "$HOME/containers/shortwgs.sif" fastp --version

# Replace paths with real HPC paths. Start with a dry-run.
bash ~/UhlemannLab/shortWGS/Go_shortWGS.sh \
  --container apptainer \
  --container-image "$HOME/containers/shortwgs.sif" \
  -i /shared/fastq -o shortwgs_out \
  -d /shared/db/wgs -k /shared/db/kraken2 -r /shared/GoWGS \
  -c 8 -n

All input paths must exist on HPC. FASTQ files, external databases, and GoWGS are separate from the image and must be prepared in HPC storage. After the dry-run passes, remove -n and run within your allocation, matching the core count to the assigned resources.

Runtime selection does not automatically distribute rules across Slurm nodes. Rule-level scheduling needs a separate Snakemake executor/profile configuration.

Keep the image and code versions together

  • Use versioned SIF filenames, such as shortwgs_v1.sif, and retain the source .image.txt.
  • Record the Git commit, Docker image ID, and SIF checksum (sha256sum shortwgs_v1.sif) in the analysis record.
  • Git stores the Dockerfiles and scripts. Archives, SIF files, and image metadata are stored separately; container-images/ is ignored.
  • Deploy common/container.sh along with the launchers. Cloning the repository includes it automatically.

These instructions and launch options are available. Images still need to be created and validated on your target HPC.
